### 2.2 Files of a domain

```
thcosmo-<domain>/
├── SKILL.md
├── references/
│   ├── formalism.md        conventions block first; equations with paper and equation number
│   ├── models.md           one model card per model (schema below); snapshot date
│   ├── results.md          theorems, no-go results, Standard-Model computed values, bounds; history
│   ├── approximations.md   validity range and error of each approximation; referee list
│   ├── open-questions.md   debates with both sides; stale claims
│   ├── sources.tsv         key, id, version, first_author, year, title, role
│   └── subtopics.tsv       key, title, from, files, status
└── deep/                   zero to six dossiers, from the gap audit
```

Placement: a prediction of one model goes in `models.md`; a result that
holds independently of the model goes in `results.md`.

**Model card** (fixed headings, checked by a test):

```markdown
### <Model name>
<!-- key: ... -->
- **Defining equations:** $...$ [src: Eq. n] (arXiv:...)
- **Parameters:** ...
- **Predictions:** ... [src: ...]
- **Consistency:** <claim> (arXiv:..., place); reply: <claim> (arXiv:..., place) or "none found"
- **Observational status:** <verdict>, <dataset>, <confidence level> (arXiv:..., place)
- **Status date:** YYYY-MM-DD
```

### 2.3 Provenance rules (the decisions, in one place)

1. Every equation and number names its paper and the place read. An
   equation with its own `[src: Eq. n]` is sourced as a whole, coefficients
   included (D10).
2. Equations are copied as the paper writes them, up to the published list
   of meaning-preserving normalisations (spacing, `\displaystyle`, brace
   style, `{\bf x}` = `\mathbf{x}`) (D11).
3. Unnumbered equation: `[src: Sect. 3.2, unnumbered display after
   Eq. 12]`; always re-read by a person at the gate (D12).
4. `sources.tsv` records the arXiv version read; places refer to it (D13).
5. A paper without HTML may be read in its PDF by a maintainer; place
   written `Eq. n (PDF vN)`; logged (D14).
6. Textbook content needs a readable source citing the textbook
   (`[sec: …]`), else "Not verified". No Crossref check until a `doi:` row
   exists (D15).
7. A known error in a source: cite the corrected version and record the
   slip in `stale-claims.md` (D16).
8. Conversions between conventions: only relations a paper states, in the
   atlas, flagged `[src]`; no conversion by an agent in the files (D17).
9. No symbolic-algebra checks before 1.0 (D18).
10. In tables, no `|` inside `$…$`: use `\lvert…\rvert`, `\vert`.
11. Model status carries a status date; status older than six months is
    flagged at refresh (D23).

### 2.4 Two-home rules (D7)

1. A non-linear or late-time extension lives with the non-linear method and
   points to the linear home.
2. A mechanism lives with its physics; its observable signature lives with
   the observable.
3. An interaction between two dark components lives with the component
   whose equation of state is modified.
4. A code question lives in `theory-codes` if it exists, else with the
   physics.
5. A measured value lives in cosmoskill; a theory skill quotes it only for
   a model's status.

## 3. The recipe for one domain

Used for every domain from the pilot on. Steps 1 to 3 build and gate the
reference level; steps 4 and 5 the dossiers.

### Step 1 — build run (research agent)

- **Before starting** (coordinator): read `git log`, every `_progress.md`
  and the gate log; at most two agents running.
- **Prompt** (coordinator fills the brackets):

  ```
  Build the skill thcosmo-<domain> of the thcosmoskill package in
  ~/Software/thcosmoskill. Date of the run: <YYYY-MM-DD>.
  Follow docs/agent-brief.md exactly. Scope and boundaries: the row of
  thcosmo-<domain> in docs/scopes-domains.md and the two-home rules.
  Anchor papers (already verified): the rows of docs/anchor-sources.tsv
  whose domains column names <domain>. Seed subtopics, to be replaced by
  the list you draw from reviews: <seed list from section 7>.
  Conventions: point to plugin/skills/theoretical-cosmology/references/conventions.md.
  Budget: 90 research calls. Write only inside plugin/skills/thcosmo-<domain>/.
  Do not commit.
  ```

- **Out**: `SKILL.md`, five reference files, `sources.tsv`,
  `subtopics.tsv`; `_progress.md` deleted.

### Step 2 — gate G1, tools (coordinator)

```bash
python3 tools/assign_keys.py && python3 tools/sync_blocks.py
python3 plugin/skills/theoretical-cosmology/scripts/verify_sources.py plugin/skills/thcosmo-<domain>
python3 tools/check_numbers.py --skill thcosmo-<domain> --list        # must print nothing
python3 tools/check_equations.py --skill thcosmo-<domain> --list      # must print nothing
python3 tools/check_transcription.py --skill thcosmo-<domain>         # zero "mismatch"
python3 tools/check_places.py --skill thcosmo-<domain>                # report only
python3 -m pytest -q
```

Done when all pass. Log: counts per class of `check_transcription` and
`check_places`, number of `eq: notation` escapes.

### Step 3 — gate G2, re-read (a second Claude session)

```bash
python3 tools/sample_statements.py --skill thcosmo-<domain> --seed <n> \
    > docs/history/tests/g2/thcosmo-<domain>-<date>.md
```

The sheet lists, to re-read in the paper at the named place (L4):

1. **Every** equation and number of `SKILL.md`, and every entry of the
   conventions block.
2. **Every** equation that `check_transcription` did not class as exact,
   and every number that `check_places` did not find at its place.
3. **A random draw of 59** from the items the tools passed (exact
   equations, numbers found at their place), or all of them if there are
   fewer than 59.

Pass (D20): no error in parts 1 and 2 after fixes, and **zero errors in the
draw of 59**, which bounds the error rate of tool-passed items below 5 %
at 95 % confidence. If the draw has an error: fix it, search the skill for
the same pattern and fix every instance, then draw a fresh 59 with a new
seed; log every draw. Cost: about half a run.

### Step 4 — dossiers (research agent, after the gap audit)

1. **Gap audit** (coordinator): write ten "how is it derived" or "which
   method" questions from `subtopics.tsv`, answer each at L2. A question L2
   cannot answer is a dossier candidate.
2. Zero to six dossiers (D21), one or two runs of up to three, with
   `docs/agent-brief-dossier.md`. Uncapped length; split past about 1000
   lines.

### Step 5 — gate G3 (coordinator, then second session)

G1 and G2 on `deep/`, and each dossier answers the audit questions that
caused it. Then set the domain's row in the hub router to **built**, update
the README table, commit, push.

### Generality check (every gate)

`tools/word_share.py --skill thcosmo-<domain>` (T11): share of citations by
first author or collaboration, and of named codes and models. Any single
group, code or model above 15 %, or the owner's own papers above 5 %, is
reviewed and either justified in the gate log or rebalanced.

## 6. Rules that hold throughout

- Nothing from memory: every equation and number with its paper and place.
- At most two research agents at once; one window a week by default (D31).
- Agents write only inside their own skill; the coordinator gates every
  run, logs it, commits to `main` and pushes; no tags from Claude (D33).
- Before any run, read `git log`, the `_progress.md` files and the gate
  log; another session may be working in the repository.
- Separate verify caches; maintainers may read cosmoskill's paper-HTML cache
  read-only (D32).
- The base follows the field's weights; the owner's own depth goes into a
  personal layer.
