# thcosmoskill — plan

Written 2026-10-30. The plan to follow from the base release (0.1.0) to
release 1.0. Design: `docs/specs/2026-10-30-thcosmoskill-design.md`. Domain
boundaries: `docs/scopes-domains.md`. Verified anchor bibliography for
seeding the domains: `docs/anchor-sources.tsv` (66 papers, all checked
against arXiv by `verify_sources.py` on 2026-10-30, 0 problems).

## Aim

A general theoretical-cosmology skill package, useful to any researcher in
the field, on cosmoskill's machinery: four levels (L1 `SKILL.md`, L2
`references/`, L3 `deep/` dossiers, L4 the paper), personal and project
layers, every equation and number traced to its paper and the place it was
read. Twenty domain skills, a hub and a refine skill at 1.0.

## How one domain is built (the recipe)

Every domain follows the same five steps; the waves below only order them.

1. **Build run** (one research agent, `docs/agent-brief.md`): subtopics
   from two recent reviews or lecture notes and the community reports, the
   five reference files, `sources.tsv`, `subtopics.tsv`, `SKILL.md`. At most
   90 research calls; no cap on sources; checkpoint after each subtopic.
2. **Gate G1 — tools** (coordinator): `assign_keys`, `sync_blocks`,
   `verify_sources` online, `check_numbers --list` empty, `check_equations`
   empty (after T2), full test suite.
3. **Gate G2 — sample re-read** (a second session): `tools/sample_statements.py`
   (T4) draws ten equations and ten numbers at random; each is re-read in
   its paper at the place named (L4). Pass: zero transcription errors and
   zero wrong places. Any error: fix it, look for the same error pattern in
   the whole skill, draw a new sample. Logged in the gate log.
4. **Dossier runs** (`docs/agent-brief-dossier.md`, revised in T5): six
   dossiers per domain, chosen from `subtopics.tsv` by where L2 cannot answer
   "how is it derived" or "which method"; two runs of three. Dossiers are
   uncapped in length and split past about 1000 lines.
5. **Gate G3 — dossiers**: G1 and G2 again on `deep/`, and a check that
   each dossier goes beyond the reference files instead of restating them.

Then the hub's router row for the domain is set to built.

## What to do, in order

### T. Theory tooling (before the pilot; coordinator, no research agents)

1. **T1 — Number checker on mathematics.** Build a corpus of theory
   statements (`tests/fixtures/theory-statements.md`: slow-roll formulae,
   PT kernels, Friedmann equations, coefficients written as fractions,
   exponents, indices, ℓ and multipole numbers, e-fold numbers) and decide
   per pattern what is a value. Extend `NOT_NUMBERS` in
   `tools/check_numbers.py` only for structure (exponents, indices,
   subscripts, ℓ values named as such); a coefficient in a result stays a
   number that needs its source. Tests for each rule.
2. **T2 — Equation check.** `tools/check_equations.py`: every statement with
   an equation (a `$...$` span holding `=`, `\propto`, `\simeq`, `\approx`,
   `<` or `>`, or a display block) holds an identifier and an equation or
   section place, or carries `<!-- eq: notation -->` when the equation only
   defines a symbol. Baseline file at zero, a test like
   `test_every_number_has_its_source`, and the sync block's mention.
3. **T3 — DOI check.** `verify_sources.py --doi` asks Crossref
   (`api.crossref.org`) for title and first author of `doi:` rows, cached in
   the same cache directory; off by default until decision D5; disclosure
   in both READMEs and the network test updated.
4. **T4 — Sampler.** `tools/sample_statements.py --skill <skill> --equations
   10 --numbers 10 --seed <n>` prints statements with file, line, identifier
   and place, for gate G2; deterministic for a given seed.
5. **T5 — Briefs.** Revise `agent-brief-dossier.md`, `agent-brief-deepen.md`,
   `agent-brief-numbers.md` and `agent-brief-refresh.md` for the theory
   contract (derivation chains in dossiers, model-status rule, equation
   flags); drop `agent-brief-rebalance.md` until a generality audit asks
   for it.
6. **T6 — Domain shape test.** A test that each built `thcosmo-*` skill has
   the five reference files, `sources.tsv`, `subtopics.tsv` with the right
   columns and statuses, a snapshot date in each file, and a conventions
   block at the top of `formalism.md`.
7. **T7 — Gate log** started at `docs/history/tests/gate-log.md` (done in
   the base) and a `_progress.md` convention for the coordinator.

Done when: all tests pass, the T1 corpus passes, `check_equations` exists
with a zero baseline. Cost: one or two coordinator sessions; no research
agents.

### P. Pilot domain and the conventions table

1. **P1 — Pilot build**: `thcosmo-lss-perturbation-theory` (decision D3),
   through the recipe, steps 1–3.
2. **P2 — Owner review of the pilot**: the owner reads `SKILL.md`,
   `formalism.md` and `approximations.md` and grades transcription,
   conventions, coverage and generality. Findings go into the brief (T5
   revision) before any other domain starts.
3. **P3 — Pilot dossiers**: recipe steps 4–5.
4. **P4 — Hub conventions table** (one research run): for the conventions
   listed in `references/conventions.md`, which reference works adopt which
   choice (the major textbooks and lecture notes, and the conventions of the
   main codes), each with its source and place. This table is what every
   later `formalism.md` conventions block points to.
5. **P5 — Example layer** rewritten to attach to the pilot's keys as well as
   the hub's.

Done when: the owner accepts the pilot; the brief is revised; the
conventions table passes G1 and G2.

### Waves A–E. The other nineteen domains

Two research agents at most at any time; the coordinator gates each run
before starting the next pair. Within a wave, order is the listed order.

| Wave | Domains | Why this order |
|---|---|---|
| A — foundations | `thcosmo-cosmological-perturbations`, `thcosmo-gr-background`, `thcosmo-thermal-history`, `thcosmo-cmb-physics` | every other domain points to their formalism |
| B — early universe | `thcosmo-inflation`, `thcosmo-primordial-correlators`, `thcosmo-cosmological-gravitational-waves`, `thcosmo-baryogenesis-phase-transitions`, `thcosmo-relics`, `thcosmo-fundamental-theory` | inflation and correlators are the heaviest; fundamental theory last, as it leans on the others |
| C — dark sector | `thcosmo-modified-gravity`, `thcosmo-dark-energy`, `thcosmo-neutrinos-light-relics`, `thcosmo-dark-matter-models` | modified gravity first: the EFT of dark energy is its home |
| D — structure | `thcosmo-nonlinear-structure`, `thcosmo-relativistic-cosmology`, `thcosmo-cosmic-dawn-igm` | the pilot already covers perturbation theory |
| E — cross-cutting | `thcosmo-theory-codes` | needs the domains' code mentions; `[doc]` facts read in one pass |

Each domain's run starts from its rows of `docs/anchor-sources.tsv` and the
seed subtopics in the appendix, which the agent replaces with the list
drawn from its reviews.

### H. Hub references (after wave C)

1. `references/review-rubric.md`: red flags and recurrent slips, each with
   the paper that corrects it, drawn from the domains' "Errors that recur".
2. `references/review-checklists.md`: one list per family, from the
   domains' "Checks a referee makes".
3. `references/field-state-2026.md`: a short digest of where each domain
   stands, superseded by each domain for its own content.

### S. Synthesis (last)

`thcosmo-tensions-model-building`, from the other skills and the tension
reviews (anchor rows for this domain), then the hub digest refreshed. This
domain is refreshed after every other domain in each later update cycle.

### L. Layers

1. The owner's personal layer (the owner's own depth on perturbation theory,
   velocities and field-level forward models), staged and kept out of the
   base, as in cosmoskill.
2. A layers test on a real domain: answering from a personal layer, as
   cosmoskill did on 2026-10-17.

### Q. Quality

1. **Generality audit** of the twenty domains: is any subject built around
   one group, school, code or model? Corrections by rebalancing runs.
2. **Level self-tests** (questions, answers and grades by Claude agents):
   a smoke test of routing and levels only, never cited as evidence of
   quality.
3. **Benchmark** with outside questions graded by theorists: design reused
   from cosmoskill's benchmark plan; run when cosmoskill's runs, to share
   graders and protocol.

### R. Release 1.0

Icon (`tools/make_icon.py` with a theory image; decision D8), version bump
in `plugin.json`, CHANGELOG, release manifest `releases/1.0.0.tsv`, README
counts (domains, sources, dossiers, snapshot date), the `claude plugin
validate` check, then the directory listing as for cosmoskill.

### X. Cross-suite integration with cosmoskill (decision D7)

A router line in each hub pointing to the other suite for what it holds;
the overlap table of `docs/scopes-domains.md` mirrored in cosmoskill's
`docs/`; optionally a shared cache (D6).

## Risks and what answers them

| Risk | Answer |
|---|---|
| An equation transcribed wrong (sign, factor, convention) | G2 re-reads ten equations per domain at L4; the brief forbids conversion and combination; conventions named with each equation |
| Memory taken for a source | rule 1 of the brief; `verify_sources` on every row; 3 of 51 remembered identifiers were wrong when the anchor list was built |
| Textbook-only results that the scripts cannot read | second, readable source required; otherwise "Not verified"; Crossref check of DOIs (T3) |
| `check_numbers` floods on mathematics | T1 calibration before the pilot |
| Model zoos (dark energy, modified gravity, inflation) swamp the files | `models.md` covers classes by literature weight, named reviews hold the long lists; the generality rule; Q1 audit |
| Fast debates (DESI dark energy, loop corrections in inflation, swampland) | both sides cited with dates; snapshot dates; refresh cycle with the synthesis last |
| Overlap with cosmoskill gives two answers | boundary table; measured values only in cosmoskill; a theory skill quotes a bound only for a model's status |
| hep-th breadth turns `thcosmo-fundamental-theory` into a string-theory review | scope limited to cosmological application; out-of-scope line in the scopes file |
| Rate limits cut a run | checkpoint after each subtopic; `_progress.md`; resume rule |
| Another session works in the repository | before any run, read `git log`, the `_progress.md` files and the gate log |

## Rules that hold throughout

- Nothing from memory; every equation and number with its paper and place.
- At most two research agents at once; the coordinator gates every run and
  logs it; agents write only inside their skill and never commit.
- Upkeep tools run once, at the end of a run; tests pass before a commit.
- Commits go to `main` and are pushed (decision D1); no tags from Claude.
- The base follows the field's weights; the owner's depth goes in the owner's
  layer.
